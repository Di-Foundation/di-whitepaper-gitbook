$Di is designed around ecosystem consumption, contribution incentives, and governance collaboration.

DI positions $Di as an ecosystem-consumptive token. It is not designed to represent equity, debt, revenue share, profit participation, or ownership of DI assets, treasury resources, or business operations.

## Service Usage Orientation

The core use cases of $Di come from AI service consumption inside the DI ecosystem.

Users can use $Di for Event Engine, AI Quant Intelligence, Compute Packs, API Services, Model Services, Agent Access, Data Services, and Enterprise Intelligence.

This makes the primary use of $Di related to product usage and ecosystem participation.

## Contribution Incentive Orientation

$Di will be used to incentivize contributions that create practical value for the DI system.

Contribution incentives focus on data quality, model effectiveness, Agent stability, historical review value, security feedback quality, developer tool usage, and ecosystem application collaboration.

This makes the incentive mechanism centered on real contribution rather than passive holding.

## Governance Collaboration Orientation

$Di will gradually participate in DI ecosystem governance.

Governance scope focuses on internal ecosystem matters, including contribution rules, data standards, model evaluation, Agent access, Compute Pack types, API permissions, ecosystem incentives, and risk-control parameters.

Governance participation serves ecosystem collaboration and rule co-creation within DI.

## Economic Flow Orientation

DI's economic flow is built around service consumption, resource input, contribution incentives, and ecosystem collaboration.

Stablecoin payments lower the service access barrier. $Di payments create native ecosystem consumption. Contribution incentives support data, models, Agents, and developer ecosystem collaboration. The Foundation treasury supports long-term construction.

This design connects $Di with DI product usage and ecosystem contributions.
