$Di 是 DI 生态中的生态消耗性代币。

它围绕真实产品使用、AI 服务消耗、算力服务额度、数据与模型贡献、Agent 协作和生态治理形成经济闭环。

$Di 的设计重点是让 DI 生态中的服务使用、资源投入、贡献协作和治理参与拥有统一的经济媒介。

## 生态定位

$Di 服务于 DI 生态内部的消耗和协作。

在 DI 体系中，用户可以通过 $Di 使用 AI 事件推演、Compute Packs、开发者 API、Agent 服务、模型服务、数据服务和企业级智能模块。生态贡献者可以围绕高质量数据、模型优化、Agent 构建、历史事件复盘、风险识别和开发者工具提交贡献，并进入贡献评估与激励流程。治理参与者可以围绕生态规则、贡献标准、任务模板、产品参数和资源分配进行协作。

因此，$Di 的核心作用是连接三类行为：服务消耗、贡献激励和生态治理。

## 服务消耗

$Di 可以用于 DI 生态内的多种服务消耗场景，包括：

- Event Engine 事件推演任务；
- AI Quant Intelligence 研究任务；
- Compute Packs 小型算力包；
- API Services 开发者调用；
- Model Services 模型能力调用；
- Agent Access 专业 Agent 使用；
- Enterprise Intelligence 企业级智能服务；
- 数据服务、报告生成和任务模板。

用户也可以通过稳定币完成服务支付，以降低使用门槛。稳定币收入将作为 DI 生态收入的一部分，用于产品建设、算力投入、模型迭代、数据采购、生态合作和长期运营。

随着 $Di 生态接入能力逐步开放和生态使用场景成熟，DI 将逐步强化 $Di 在服务消耗、生态激励和治理协作中的原生角色。

## 贡献激励

$Di 将用于激励 DI 生态中的真实贡献。

可被激励的贡献包括高质量数据、有效模型、稳定 Agent、历史事件复盘、风险识别、安全反馈、开发者工具、任务模板、企业集成、生态教育和社区建设。

DI 将以贡献质量、可验证性、长期价值和系统提升效果作为激励依据。

## 生态治理

$Di 将逐步参与 DI 生态治理。

治理范围聚焦于 DI 生态内部事务，包括贡献规则、数据标准、模型评估、Agent 接入、Compute Packs 类型、API 权限、生态激励、任务模板和风险控制参数。

治理的目标，是让长期参与 DI 建设的用户、开发者、研究员、数据方、模型方、Agent 构建者和生态合作方，能够共同参与生态演进。

## 经济循环

$Di 的经济循环来自真实服务需求和生态贡献。

用户使用 DI 产品产生服务消耗，服务消耗推动算力、模型、数据和 Agent 需求，生态贡献者围绕这些需求提供数据、模型、Agent、复盘和工具，系统再通过贡献激励和治理协作提升整体能力。

这个循环使 $Di 与 DI 的产品使用、资源投入和生态协作发生连接。
