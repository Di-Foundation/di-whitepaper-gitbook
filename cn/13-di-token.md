# 13. DI Token 用途

DI Token 连接产品访问与服务使用。不同场景采用不同方式：数据看板对应持仓资格，推演与 Agent 服务对应使用消耗，量化产品对应平台利润分成。

| 场景 | 机制 | 作用 |
| --- | --- | --- |
| 数据看板 | 持有 DI | 获得看板使用资格 |
| Event Engine | 消耗 DI | 支付推演服务 |
| 个人 Agent | 消耗 DI | 支付任务执行与工具调用 |
| Agent 网络 | 消耗 DI | 支付网络服务与协作任务 |
| 量化产品 | 利润分成 | 平台从产品利润中按约定比例获得收入 |

## 持仓与支付

持有 DI 以获得看板使用资格，与为一次服务支付 DI 是不同机制。前者是访问条件，后者对应产品或 Agent 提供的服务。

DI 用于支付相应服务，支付与代币销毁是不同机制。个人 Agent 与网络服务的支付场景将随对应产品阶段开放。

## 量化分成与回购

量化平台从产品利润中按约定比例获得分成。该分成属于平台业务收入，不等于每个 DI 持有人直接获得产品利润。

DI 将部分业务收入用于代币回购，连接实际产品使用、业务收入与代币需求。回购机制不构成固定回报、价格目标或本金保护。

## 与贡献机制的关系

DI 设置有效贡献奖励与生态共建机制，用于支持有价值的数据、研究、策略及产品合作。贡献资格通过相应验证确定。

具体持仓门槛、服务价格与产品费用以相应产品规则为准。
