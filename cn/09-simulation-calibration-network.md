Simulation Calibration Network 是 DI 用于持续优化模型表现、Agent 协作、事件推演、量化研究和生态贡献质量的校准机制。

它首先服务 Event Engine 的事件推演闭环，但长期会成为 DI AI + Crypto 智能生态的质量反馈系统。每一次事件分析、市场变化、结果偏差、历史复盘和贡献验证，都会成为 DI 优化数据权重、模型能力、Agent 分工和产品输出的重要材料。

DI 正在构建的是一个能够持续推演、持续复盘、持续校准的智能生态。

## 为什么需要推演校准

加密市场变化速度极快。

同样类型的事件，在不同市场周期、流动性环境、杠杆水平、监管背景和叙事阶段，可能产生完全不同的结果。

一次监管新闻，在流动性充裕时可能只是短期扰动；在市场信心脆弱时，可能演化为更大范围的风险扩散。一次链上攻击，可能只影响单一协议，也可能因为组合性风险、稳定币流动性和市场恐慌扩散到更多生态。

因此，事件推演系统需要记录过程、跟踪演化并持续校准。

## 事件发生前：推演记录

在事件发生前或事件早期，Event Engine 会记录推演任务的完整过程。

记录内容包括事件输入、事件结构化结果、调用的数据源、参与分析的 Agent、关键假设、情景路径、风险指标、输出结论和不确定性提示。

这些信息会形成可追溯的推演记录，为后续复盘提供依据。

## 事件发生中：动态跟踪

事件演化过程中，DI 会持续跟踪市场变化。

系统会观察链上资金流、交易所流入流出、稳定币流动性、衍生品杠杆、清算风险、舆情叙事、相关资产波动和宏观变量联动。

动态跟踪可以帮助系统判断事件是否正在沿某一情景路径演化，或者是否出现新的风险分支。

## 事件结束后：复盘校准

事件结束或影响阶段性减弱后，DI 会进行事后复盘。

系统会比较此前推演与真实市场表现之间的差异，包括哪些资产影响判断较为准确，哪些风险路径没有发生，哪些尾部风险被低估，哪些数据源更早捕捉到变化，哪些 Agent 的判断更稳定，哪些情景模板需要修正，哪些指标阈值需要调整。

复盘结果会反向用于优化数据权重、模型参数、Agent 表现、事件分类体系和情景推演模板。

## 校准对象

Simulation Calibration Network 会持续校准多个系统组件。

数据源可信度会根据不同事件中的表现被评估。模型权重会根据事件分类、相似事件检索、风险判断和叙事理解表现进行调整。Agent 表现会在事件复盘中被记录，用于优化未来任务分配。情景模板会根据真实事件演化不断改进。风险阈值也会随着市场结构变化持续更新。

## 贡献协作机制

推演校准网络也是 DI 生态协作的重要组成部分。

研究员、数据贡献者、模型开发者、Agent 构建者、安全团队和社区成员，都可以围绕历史事件复盘、数据纠错、标签补充、情景模板优化和模型校准提供贡献。

这些贡献的价值，体现在对 DI 系统长期质量的提升。

DI 将围绕高质量数据、有效复盘、模型改进、Agent 优化和风险识别，建立贡献协作与生态激励机制。
